# 身份与事务契约 v1

> 本文记录现有v1运行代码契约，不是新两级目录/多规则模板的设计依据。新后端审阅稿见[设计入口](../design/v1/00-设计入口.md)；代码切换后同步重新导出契约。

2026-10-27，T0/T1本批实现范围。以`backend/app/schemas/identity.py`、生成的[JSON Schema](identity-v1.schema.json)、[OpenAPI](openapi.json)及`frontend-shared/src/api.generated.ts`为同一套契约。未声明题目输出、生成器、能力分配与文件成功提交的全部契约已冻结。

## 会话接口

| 接口 | 行为 |
| --- | --- |
| POST /api/v1/session | 空JSON；有效Cookie复用user_id并换发CSRF，无有效Cookie建立新匿名主体，返回持久Cookie及会话额度状态 |
| GET /api/v1/session | 查询会话，不旋转CSRF；有效期不足7天时续至90天，Cookie与数据库同时更新 |
| POST /api/v1/session/csrf | 空JSON、有效Cookie及严格Origin；换发CSRF，旧值立即失效 |
| POST /admin/api/v1/session/login | username/password；失败不区分未知用户、错误口令或停用账户；成功设置独立8小时会话 |
| GET /admin/api/v1/session | 返回管理员身份、北京时间和固定到期时间，不续期 |
| POST /admin/api/v1/session/csrf | 管理员Cookie及管理员Origin，换发管理员CSRF |
| POST /admin/api/v1/session/logout | 管理员Cookie、Origin、CSRF，撤销服务端会话并删除Cookie，204无响应体 |

所有写请求检查对应Origin白名单和application/json。建立会话/登录/换发CSRF不要求旧CSRF，其余写操作通过`auth.dependencies.current_user/current_admin`检查CSRF。Cookie名称、路径按01；不设置Domain；HTTPS开启Secure，本机HTTP才能显式关闭。响应及错误均no-store；数据库只存Cookie/CSRF的SHA256，不存原值。POST bootstrap换发CSRF属于明确实现决定，GET不换发；前端仅在CSRF_INVALID时换发并最多重试一次。

所有业务时间按固定微秒精度`+08:00`返回，Cookie Expires属于HTTP协议字段，按GMT编码。`can_generate`只表示身份额度可准入，不表示模板、队列或PDF服务已就绪。当前未开放生成API。

## 限流与密码

- 新主体：同一IP HMAC每小时最多20个；有效会话bootstrap不计新主体。共享IP不会合并主体或历史。
- bootstrap及两类CSRF换发：合计每IP每分钟最多60次；这是本批可调整负载保护默认值。
- 管理登录：每IP5次失败/300秒。高成本校验前在短事务预占名额，成功后删除该事件；并发在途校验暂占名额，进程崩溃时最多等待原300秒窗口，不允许并发绕过。
- 技术限流事件仅保留24小时，受理限流请求时清理更旧事件；不清理匿名身份或正式历史。
- HMAC密钥由init-security生成并保存在数据库外的独立0600文件；不自动轮换，备份时单独保管。原始IP不入库。启动参数`--no-proxy-headers`，本批不信任任意转发头。
- 管理员密码使用argon2-cffi的Argon2id：memory_cost=19456 KiB、time_cost=2、parallelism=1；哈希在写锁外执行，算法参数存入哈希并在登录时检查升级。参数参考[OWASP密码存储指导](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

新增错误：403 ORIGIN_INVALID、401 LOGIN_FAILED、503 SERVICE_NOT_READY。SQLITE_BUSY/LOCKED映射503 DATABASE_BUSY与Retry-After，数据库路径/原始异常不返回；限流429附Retry-After。

## 事务边界（供T4接入）

`require_user(session, raw_cookie, now)`在调用方Session内验证会话和主体；`auth.dependencies.current_user`只负责HTTP鉴权和续期，返回不可变Principal，不代替最终业务事务重验。

`check_generation_admission(session, user, now)`：T4在BEGIN IMMEDIATE内先检查同key幂等，再调用该函数检查主体状态、queued/running任务、成功冷却。函数不提交事务、不设置冷却。随后T4检查内容epoch、队列容量、IP生成受理额度并插入job；上述操作必须在同一事务。job的部分唯一索引防止同主体不同key并发插入两个活跃任务，幂等唯一键防止同key重复行。

`record_generation_success(session, user, now)`：T4先完成数学验证与所需PDF落盘，在最终短事务重新验证租约、模板状态、资产条件及job尚未成功，再发布快照/ready索引/job成功，并调用该函数写成功时间和+600秒。函数不执行文件操作或自行提交。它本身不验证PDF或保证幂等，不能独立对外暴露；同key重放必须由T4返回原任务而非再次调用它。失败/取消不调用该函数，事务失败回滚全部时间字段。

任务模型本批仅建立存储契约和约束，不提供任务受理、worker或成功提交服务；`intermediate_snapshot`及`content_schema_version`留给07的恢复流程。
