# 首个乘法内容契约（已实现子集）

> 本文记录现有v1运行代码契约，不是新两级目录/多规则模板的设计依据。新后端审阅稿见[设计入口](../design/v1/00-设计入口.md)；代码切换后同步重新导出契约。

本批冻结 `integer_multiplication_v1` 1.0.0 与 `MUL_VERTICAL` 草稿的纯计算边界，不代表一期所有题型、目录接口或发布事务已经冻结。

## 代码与数据

- 后端唯一DTO：`backend/app/schemas/content.py`；共享TypeScript由`scripts/export_contracts.py`生成。独立JSON Schema见[multiplication-v1.schema.json](multiplication-v1.schema.json)。
- 生成器：`backend/app/generators/multiplication.py`；不访问HTTP、ORM、时钟或文件存储。代码注册表`registry.py`提供版本、schema和SHA256部署指纹；调用返回新对象，不允许修改全局能力。
- 首个草稿种子：`content/seeds/mul-vertical-v1.json`。仅含上册候选目录中的一个主题/O002/一个目标/一个模板，不是全册种子。0003及`seed-content`命令现已支持幂等入库，同时创建空的下册候选目录；未自动执行到用户运行库。
- 目标code `O002_COLUMN_MULTIPLY_V1`仅对应种子中O002修订1。后续T2必须将实际目标修订及其hash匹配到此代码目标；不能仅凭用户提交code宣称兼容任意新修订。

## 输入、采样和验证

`validate_config`重验配置；`supports`核对目标、题型、难度；`sample_params`在50次内寻找合法参数；`build_question`构造固定参数的题目；`verify_question`独立验证；`semantic_signature`按目标、任务和有序因数去重；`generate_paper`生成1至max_per_paper道同模板题；`capacity`精确枚举合法空间。

seed为1–128字符字符串，通过SHA256初始化局部随机源。算法/配置/seed/题序相同，内容及UUID相同；不依赖Python进程hash。固定样例与整卷由调用者传入seed。UUID用于内容标识，不作为历史访问凭证。

本模板只支持answer/vertical及basic、standard。basic为100–299乘11–19，因数无零，最多2次进位；standard为100–999乘11–99，允许零，最多9次进位。进位按逐列产生非零进位计数，包含两个部分积计算和相加过程；同一列进位数值大于1仍只计一次。这是当前可调整实现默认值，非已通过教师审定的难度划分。

单候选至多50次（含重复），整卷至多max(200,题数×50)次参数采样；耗尽抛`GenerationError(code='GENERATION_EXHAUSTED')`，不悄悄更改题数/档位。worker硬超时仍须由T4补充。`capacity`只用于离线检查/worker，不在API请求或写事务内运行。

## 内容与竖式

当前只实现text/math块、整数numeric答案和竖式乘法render_spec。其他diagram/table/choice/drawing暂不接受；不以任意dict绕过未知类型校验。schema_version=1保存于题目，未来快照继续保留该版本。

render_spec中的`tens_partial`为已经乘10后的实际部分积，例如308×26为6160；`tens_shift=1`描述位值，渲染器**不得再次乘10**。ones_partial为1848，result为8008。学生版隐藏答案、部分积和解析，只渲染算式及留白；解析版显示完整过程。两种模式现已由frontend-shared的QuestionRenderer.vue实现，并通过SSR结构检查；真实打印和后端PDF仍未验收。

`verify_question`用重复加法重算两个部分积及总积，并比较题干、三步解析、答案和layout；不调用build_question或render_spec来制造所谓独立答案。text/math始终是数据，后续前端不能用v-html直接插入；本批没有开发LaTeX执行器。

## 离线报告与发布边界

运行库现在支持首个乘法草稿的GET/PATCH聚合编辑；可调整既有profiles和显式固定用例，保存清空有效题量并递增lock_version。目标与生成器不在本轮可编辑字段内。编辑后的内容hash覆盖运行库聚合输入，不能继续套用种子离线报告。接口、事务和实际检查见[模板草稿编辑验证](../implementation/模板草稿编辑验证.md)。

`scripts/validate_multiplication.py`读取固定草稿，验证5个固定正例、每档100个随机样例和每个候选题量20组整卷，并精确枚举容量。报告绑定种子输入、schema、算法/校验版本和源文件指纹；时间为固定微秒北京时间。

`checked_count_options`仅是开发检查结果，不能直接填充公开能力。报告不创建validation_run、不批准人工review、不发布模板，也不改变content_epoch或冷却。正式能力仍需目录/模板入库、后台验证任务、hash绑定的人工审题、发布和数量策略共同决定。打印结构、真实PDF、A4样张仍待验证。

工程离线脚本保持上述边界。另已实现基于运行库快照的正式template_validate任务和独立worker：创建validation_run、保存覆盖与失败明细/固定样题，只在hash/租约仍有效且检查通过时写回有效题量，详见[验证任务记录](../implementation/模板验证任务与worker验证.md)。人工审题/发布操作也已实现，须由管理员明确提交，不自动批准；见[发布验证](../implementation/人工审题与内容发布验证.md)。


## 每行题数（2026-10-28）

`QuestionLayout`增加严格整数`questions_per_row`（1–5，默认2）和`solutions_per_row`（1–5，默认1）。后台可按难度设置，持久化到原profile.layout_config，数学生成输出会复制到题目layout。已发布模板仍不可原地修改；保存草稿后必须重新验证与审题。旧开发输入未含字段时保留2/1兼容默认值。

PDF按每题快照分别组成学生/解析行，配置变化时新起一行；禁止将客户端非法列数传入CSS。可使用开发样张命令的`--questions-per-row`和`--solutions-per-row`参数检查指定组合；该命令读取离线种子，不读取后台运行库，不代表后台模板已发布。


## 大题与小题标题（2026-10-28）

按用户确认，题型说明集中放在大题标题，使用中文序号“一、二、三……”；小题使用阿拉伯数字题号并保留题目内容，不逐题重复题型说明。当前只支持竖式乘法，学生题面与独立解析部分各展示一次“一、竖式计算”，小题如“1. 177 × 24”。后台审题样张及任务详情采用相同层次。后续增加选择、填空等题型时再按实际题型分大题，不因本次标题调整宣称已经支持这些题型。

本次仅修改共享展示和打印布局，不改数学题目快照/答案。已保存PDF继续复用原文件，新渲染PDF采用新标题；更新打印资源后须重启worker重新完成真实探针。


## 小题间距与十位部分积展示（2026-10-28）

题号与题干使用独立元素，间隔0.75em，避免“1. 2 × 3”被读成小数。竖式十位部分积的底层tens_partial继续保存完整位值（如3540），显示时仅去掉最后一个占位0，并保留一位数字宽度的不可见占位，使354向左对齐十位；1000显示为100错一位，不删去数值本身的0。文字步骤仍显示3540等完整数值。占位在后台打印样张的可见性覆盖下仍保持隐藏。
