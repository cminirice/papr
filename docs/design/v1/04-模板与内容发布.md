# 模板样例、验证、审题与发布

更新：2026-11-05。核心流程已实施，具体数据结构与接口以02、03为准；本文的扩展建议未全部实现，实际边界见[联调记录](../../implementation/两级目录与多规则后端联调.md)。

## 1. 状态与编辑

模板是稳定身份；内容由版本保存。建议一个模板同时最多一个draft，多个sealed历史版本，只有一个current_published_version_id。模板enabled控制开放，版本sealed表示不可变，不等价于当前开放。

未发布草稿可编辑；已发布后编辑复制新草稿，旧版继续开放。保存时重算content_hash，之前的样例、验证和审题保留追溯但不再满足新hash的发布条件。审核拒绝不影响线上旧版。

## 2. 完整样例

管理员提交版本id+content_hash生成样例任务，使用与真实出卷相同的规则分配、数学验证、语义去重、共享渲染器和PDF保存流程。严格按实际每条题数、两种列数、A4页边距生成，不抽每条一题冒充整卷。

样例任务固定seed与版本快照；重新生成是新任务、新seed。学生版和解析版同源，答案开关不重新出题。样例可下载两份PDF并查看逐题解析；保存内容hash、组件/验证器/字体/打印资源/浏览器指纹和PDF hash。管理员样例不消耗匿名冷却，不写用户历史。

## 3. 自动验证

- 目录必须两级，规则叶子属于版本一级目录，关联组件存在且启用，worker实际可用。
- 所有参数、题型、呈现、难度必须落在组件实际能力内，数量和总量不能越界。
- 固定样例、边界样例、答案与解析一致性；每条及跨规则重叠容量证明；随机多seed整卷检查（建议20组，次数写入报告）。抽样通过不代替容量证明。
- 每条题数/整卷总数、全卷去重、混合题型分节和连续小题编号正确。
- 至少生成一套真实双份PDF，解析器检查非空、页数、文本与字体；中文、长题、1～5列、跨页留白与标题随题的视觉检查作为人工审题的一部分。

组件声明支持不等于验证通过。参数空间不足时明确指出规则和可用容量；管理员仍可调整配置，不允许系统偷偷少出题。

## 4. 人工审题与发布事务

管理员打开完整样例，审核教学合理性、答案、解析、难度及A4布局。记录approved/rejected、理由、操作者、样例hash和对应validation_run。自动数学不通过时不能靠人工通过覆盖；人工负责语义、教学与视觉判断。

发布短事务重新确认：目标draft内容hash不变；最新有效自动验证和通过审核匹配hash与当前依赖指纹；目录/关联/组件仍启用，worker可用；expected_revision匹配。封存版本、切发布指针、开启模板并追加release_event/audit。失败整体回滚，旧发布版不受影响。

不采用随意覆盖published JSON的方案，也不使用全站epoch变化让所有无关任务失败。受影响依赖逐项比对。

## 5. 停用、替换与回退

模板停用后立即从公开列表/详情消失；新任务不受理，排队任务可标失败，运行任务必须在最终提交前检查并以CONTENT_CHANGED失败，不启动新冷却。

建议发布指针切换后，旧版本尚未完成的任务也不再发布成功，要求用户重新选择当前版；此规则确保“所见当前开放内容”严格一致，代价是更新时少量在途任务需重试。已成功历史仍下载原文件。

回退只能指向本模板sealed历史版，必须确认当前组件指纹和配置仍满足验证/审题证据；指纹变化则重新验证和审题后回退，不能盲目恢复。启用同样重验有效性。

目录改名不重写已发布版本名称快照；停用目录或解绑组件则使依赖模板不可用。非关联模板不受影响。

## 6. 从零发布案例

1. 新建一级目录“计算专项”；在其下新建二级目录“乘法巩固”。
2. 在叶子关联已部署的整数乘法、含零乘法组件。
3. 新建模板“每天十分钟 · 乘法”，标签“乘法、专项”，选择该一级目录。
4. 添加基础竖式6题与含零提高竖式3题，均选“乘法巩固”，每行2题，总计9题。
5. 保存草稿，生成完整9题样例，查看学生版和解析版；运行自动验证。
6. 管理员审题通过，发布；用户模板列表出现该模板。
7. 用户确认9题并生成，两份PDF与成功事务完成后进入冷却；历史可反复下载。

以上描述联调完成后的目标流程。当前高保真不执行真实发布，现有v1后端也尚未实现这一新多规则契约。
