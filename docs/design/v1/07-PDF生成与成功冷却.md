# 多规则整卷、PDF与成功冷却事务

更新：2026-11-05。核心流程已实施，具体数据结构与接口以02、03为准；本文的扩展建议未全部实现，实际边界见[联调记录](../../implementation/两级目录与多规则后端联调.md)。

## 1. 受理

API先校验身份、CSRF与输入，计算payload_hash。同主体同key同payload返回原任务；不同payload拒绝。新请求在BEGIN IMMEDIATE短事务中再次检查幂等、当前发布版本/hash、模板/目录/关联/组件状态、worker指纹、已有活跃任务、next_generation_at和队列容量。

插入queued任务与不可变plan_json：模板版本与规范化配置hash、目录/标签名称快照、全部规则及题数/顺序、组件/验证器/渲染指纹、审题和验证证据、schema版本、固定master_seed。规则seed从master_seed+稳定rule_id派生。不在准入事务做数学或PDF，不写新冷却。

## 2. 执行与租约

worker通过原子更新领取任务，生成新lease_token，attempt加1。持续续租；每次写进度、中间快照、资产与最终状态都带job_id/attempt/token条件。过期worker不能续旧租约、修改新attempt或发布资产。

建议最多两次attempt，数学20秒、双份PDF60秒、单attempt90秒作为初始配置，按200题边界压测调整。外部子进程有硬超时，失败回收进程树。内部重试不换seed，不创建新用户任务。

先按规则生成完整试卷并独立校验，维护全卷签名集合；容量不足/重复耗尽整体失败。保存intermediate_json及hash，再用同一快照渲染学生版和解析版。模板停用等不可恢复内容错误不自动重试；瞬态渲染/IO故障可有限重试。

## 3. 排版与文件

共享题目schema和渲染器，题型大题用“一、二……”标题，小题独立题号留间距，竖式十位部分积错位且不显末尾零。A4、15mm边距，每行1～5题，按实测高度整行分页，标题跟首行；超过页宽/页高返回布局错误，不能裁掉内容。学生卷不展示生成时间，姓名与手填日期保留。解析与学生题目同源，解析默认同列数，可单独配置。

学生PDF只有试题；解析PDF建议保留现有“试题＋另起页解析”方式，文件种类固定student_pdf/solution_pdf。字体与资源随部署提供，不加载用户URL；等待字体和render-ready，再生成并检查非空、页数、解析、文本及hash。

PAPR_GENERATED_ROOT为独立绝对路径，不公开为静态目录。storage_key由服务端生成`yyyyMMdd/<uuid>.pdf`，日期按资产首次登记Asia/Shanghai确定；跨午夜重试使用新attempt资产路径，不能移动旧文件冒充当前资产。

## 4. 文件与数据库提交边界

1. 登记当前attempt/token的pending资产和唯一storage_key，paper_id暂空。
2. 写同文件系统唯一临时文件，校验PDF及hash，fsync文件；以不可覆盖方式原子发布最终名并fsync目录。旧attempt与新attempt绝不同路径。
3. 两份PDF均落盘后开启成功短事务，核对当前租约、模板仍启用且发布指针仍指向受理版本、所有依赖有效、内容/资源指纹一致以及文件元信息。
4. 同一事务写paper、全部paper_question快照、两个ready资产、job.succeeded，并写anonymous_user.last_success_at=now、next_generation_at=now+600秒。任一失败全部回滚。
5. 下载仅允许归属当前用户且关联成功paper的ready资产。pending文件即使已落盘也不能下载。

SQLite与文件系统不具备跨介质原子事务；这里保证不向用户发布半成品。事务内不渲染、不做长耗时文件扫描；文件hash预先算好，最终路径由不可覆盖发布保证身份，提交前快速检查存在与元信息。

## 5. 失败与恢复矩阵

| 故障 | 恢复 / 用户结果 |
| --- | --- |
| 数学校验失败、容量不足 | job.failed，不保存成功paper、不写新冷却 |
| 只生成一份PDF或磁盘满 | 整体失败/有限内部重试，pending不可见，不冷却 |
| 文件落盘后DB提交失败 | 当前有效租约下核对快照、hash、依赖后复用产物重试提交；否则新attempt生成隔离资产 |
| worker崩溃或租约过期 | 回收器以条件更新转为可重试或failed；新token隔离旧worker |
| 内容发布/启停变化 | 最终检查CONTENT_CHANGED失败；不以无关模板变化拒绝 |
| 成功响应丢失 | 查询原key/job返回同一paper和原冷却截止，不再延长 |
| queued取消 | 终态取消，释放活跃限制，不写冷却；running取消暂不支持 |
| 成功后文件丢失/损坏 | FILE_UNAVAILABLE；管理员从同快照修复，不重出题、不改变成功时间或冷却 |

孤立pending与失败attempt文件须先确认无活跃租约和引用，再按技术垃圾规则清理；ready文件不混入垃圾清理。修复同样有租约和不可覆盖路径，新旧ready索引原子切换，保留审计。

## 6. 必须验收

不同key并发只受理一个；同key重放；成功599/600秒边界；失败/取消不冷却；两份PDF任一失败；过期租约隔离；文件落盘后提交失败；模板/目录/组件在途停用或发布切换；成功响应丢失；历史鉴权；跨午夜路径；混合组件重叠去重；100/200题与1～5列真实A4；中文字体；下载复用不更新冷却；备份恢复与文件修复。

本稿不把前端样例或旧单模板测试当作新多规则后端验收。

## 2026-11-11 Linux部署适配

独立PDF检查在macOS继续使用CoreGraphics，在Linux使用锁定的pypdf。两者均检查文件边界、非加密、1～100页、纵向A4，返回一致的文件大小/hash/页数协议；Linux另拒绝旋转和非默认UserUnit。检查通过不替代人工版面审核。worker取消macOS平台限制，仍必须经过真实渲染、解析、落盘读取探针才报告就绪。Ubuntu 22.04运行环境和配置SQL导入见[部署手册](../../manual/Ubuntu22.04部署.md)；本机测试不等于Linux实机验收。
