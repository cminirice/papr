# PDF文件保存层（2026-10-28）

本批接入文件系统保存与完整性检查基础，尚未接通用户出卷worker、数据库资产表或下载API。新任务准入仍关闭；文件保存完成不等于业务成功，也不启动600秒冷却。

## 实现

- `backend/app/services/pdf_storage.py` 接收服务端预留的两个UUID与登记时间，同时校验学生版和解析版。日期以登记时北京时间固定，写入跨午夜不改目录；不接受客户端路径或URL。
- 每份PDF上限32MiB，独立解析子进程上限10秒；检查可解析、1–100页、纵向A4、大小和SHA-256。当前解析版包含原题及另起页答案，要求页数大于学生版。
- 两版都校验通过后，写入同目录独占临时文件，文件权限0600，执行文件同步。采用同文件系统原子硬链接发布，再删除临时名称；最终路径已存在时失败，绝不覆盖。生成根目录的父目录需预先配置，根目录和日期目录按0700创建并同步目录项。
- 两份文件及目录均同步完成后才返回元数据。第二份发布失败可能留下第一份孤立文件，调用方不能发布任何ready索引；保存层不会擅自删除最终路径。重试必须分配新资产ID，孤立文件后续按任务租约和回收策略处理。
- 回读采用已打开目录定位文件，拒绝日期目录/最终文件符号链接和特殊文件，核对大小及SHA-256，返回实际验过的字节；不存在“检查后重新按路径打开响应”的间隙。此方法本身不提供用户鉴权，未来下载API必须先校验归属、ready状态和成功试卷。
- 将既有CoreGraphics检查器移入后端供子进程复用，原开发CLI继续可用。仅支持macOS；其他平台解析失败，不假装有跨平台解析能力。解析不代表中文字体覆盖或视觉审查通过。
