# 后台记录统计与发布浏览器验收（2026-10-28）

本批完成用户要求的两项工作：后台完整发布流程的真实浏览器验收，以及生成记录和基础统计。使用单终端实施；当前目录仍未接入Git，未创建提交、推送或部署。

## 页面与接口

管理员登录后可在“内容管理”和“生成记录与统计”间切换。

- 记录按提交时间倒序，支持北京时间日期、任务类型、状态筛选与游标分页。默认最近7天，单次最多93天，每页默认20、最多100条。
- 展示任务状态/阶段、尝试次数、提交/开始/结束时间、受控失败原因、模板版本、主题和题量。
- 详情复用共享题目渲染器展示已提交试卷的只读快照；验证任务展示验证结论、失败明细和样题。未提交中间题目不可见。
- “查看来源模板版本”定位任务所用的具体版本，不默认跳到最新草稿。
- 新增GET `/admin/api/v1/overview`、`/admin/api/v1/jobs`、`/admin/api/v1/jobs/{id}`；必须有管理员会话，普通用户访问返回401。接口不返回原始任务payload、身份凭证、租约或文件路径。
- 更新共享TypeScript、JSON Schema和OpenAPI；没有新增依赖。

## 统计口径

所有日期以北京时间的半开区间查询，首日00:00包含、末日次日00:00排除。

| 指标 | 口径 |
| --- | --- |
| 受理任务 | paper_generate按created_at计数，同key重放不新增任务 |
| 成功出卷 | 已成功提交Paper按generated_at计数，每张一次，不因两份PDF、多道题、重试或后续撤下而重复/扣减 |
| 失败、取消 | paper_generate终态failed/cancelled，按finished_at计数 |
| 活跃匿名主体 | 日期范围内提交有效出卷任务的owner_user_id去重，不是实际人数；期间数不按每日数相加 |
| 当前队列 | 全部日期的出卷/验证queued和running分别计数 |

统计筛选只使用日期，任务类型和状态只筛选列表。跨日任务受理和完成可落在不同日期，所以受理数不要求等于成功/失败/取消之和。验证任务执行成功与内容验证通过分别展示，不把验证任务当作成功试卷。打印意向尚未采集，不展示实际打印成功次数。

迁移0008只增加`job(kind,created_at,id)`、`job(kind,status,finished_at)`和`paper(generated_at,id)`三个索引，降级仅移除索引。未迁移运行数据库、初始化管理员或更改真实内容发布状态。

完整发布浏览器测试从**只有草稿种子**的临时数据库开始，逐步点击：

1. 登录、查看配置、提交验证；实际独立Python验证子进程完成检查。
2. 查看样题；验证无审题通过记录时不能发布、不完整确认被拒绝、审题“不通过”阻止发布。
3. 在测试库勾选样题/打印确认并提交模拟通过记录；切换学生版/解析版显示。
4. 验证未发布前置修订时不能发布；分别发布知识点和训练目标修订。
5. 发布第一版，停用，再启用。
6. 复制第二版、修改题目列数、保存、重新验证/模拟审题并发布。
7. 切换第一版并回退，核对当前发布指针和旧版列数。
8. 后台查到两条验证任务，查看报告，再定位对应来源版本。

出卷浏览器测试实际通过Chrome生成两版PDF、下载和恢复历史；后台显示成功出卷1次，失败状态过滤为空但统计仍为1；查看3道已保存题目，来源指向第一版而非新复制的草稿。测试浏览器时区为洛杉矶，页面保持北京时间。已查看后台统计页面截图。

审题勾选仅为测试fixture验证发布约束，不是模型替管理员批准实际题目；没有操作真实打印机。测试使用真实HTTP、构建后的Vue、真实SQLite与执行服务；worker循环在测试线程中调度真实子进程，未声称生产进程托管已验收。
