# 用户任务准入与快照验证

日期：2026-10-28。单终端串行开发；数据库、接口、前端继续统一北京时间。未修改外部工程、真实数据库或真实管理员/内容状态，没有推送或部署。

## 完成本批

- 复用0002的job表，迁移头仍为0006，无新增依赖。
- 用户任务接口：POST `/api/v1/paper-jobs`；GET `/api/v1/jobs`和`/jobs/{id}`；POST `/jobs/{id}/cancel`。列表支持同时间下稳定的created_at+id降序分页和状态过滤；后台任务、他人任务统一404。
- 受理事务：重验用户会话和CSRF，先查同key；再检查执行器、用户活跃任务与成功冷却、当前能力epoch/可行组合、全局活跃队列上限10（含模板验证）、每IP每600秒最多12次受理。写job与IP事件同事务，受理失败不占成功冷却。
- 固定内部PaperPlan：规范化请求、32位hex随机seed、模板/profile/组件ID及hash、具体参数、验证与审题记录、知识点与目标修订、固定模板语义、目录快照。受理不做数学计算，不把seed/内部参数/题目快照发给浏览器。
- 提供后续worker最终事务可复用的原计划有效性校验；不因重新发布而静默换模板，不因无关epoch改变重写输入。尚未接入真正成功事务。
- 排队可取消，重复取消返回原结果，running及其他终态拒绝取消；同key可重放终态，失败后可用新key。取消不设置新冷却。
- 用户端增加任务面板、时间/状态、排队取消、分页和活跃任务轮询。网络错误不当作生成失败，不自动用新key重发出卷请求。新任务按钮仍未开放。
