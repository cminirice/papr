# 用户出卷闭环与补充验证（2026-10-28）

本批完成用户worker、试卷/题目/资产持久化、同一成功事务、历史及鉴权下载，并接上用户页面的生成和PDF入口。随后按用户要求复查此前未验证项目。以下保留最初受限环境的检查记录。2026-10-28用户启用按需提权后，真实Chrome闭环、浏览器生成/历史/下载与后台列数保存、干净联网安装已补验通过，详见[最新验证记录](权限恢复后的真实集成验证.md)。一期完整验收仍包含人工审题、实物打印及部署检查。

## 实现内容

- 0007增加paper、question、question_knowledge、paper_question、file_asset及pdf_worker_state。迁移是固定DDL；有历史试卷/资产时禁止自动降级删除历史。未迁移运行库、未替用户初始化管理员或批准/发布真实模板。
- worker在短事务领取任务、续租、保存不可变快照与登记pending资产。数学、PDF渲染、解析、文件保存/回读在写锁外完成。30秒租约、等待子进程时约2秒续租，崩溃最多两次尝试；重试保留固定seed/快照并使用新资产路径。
- 成功事务再次检查租约、用户、原模板发布/验证/审题证据、快照和pending资产归属，一次写入试卷、题目、ready资产、成功任务及600秒冷却。失败不新增冷却；文件已保存但提交失败时保持不可见，后续由过期租约恢复。失败文件暂不自动删除。
- PDF运行路径由服务端配置。worker启动时先真实渲染两版、独立解析、保存并回读，探针通过后才发布30秒就绪心跳。API核对配置指纹和心跳；配置改变需重启worker。没有跳过探针的开关。
- Node启动Chrome时，通过私有目录内的启动包装器记录浏览器进程组PID。超时、失租及正常退出会清理自有Node/Chrome进程组；SIGTERM进入清理流程。该机制不依赖系统进程枚举。
- 新增GET `/api/v1/papers`、`/papers/{id}`和`/files/{id}`。只显示本主体已成功且未撤下的试卷；下载检查ready状态、所属试卷和大小/hash，返回已验证字节并保留Cookie续期。非本人404，缺失/损坏503；历史不受模板后来停用影响，不延长冷却。
- 用户页新增生成按钮、保留key和原配置的“确认提交结果”、历史双版PDF下载与打开打印。共享DTO/JSON Schema/OpenAPI已同步。

## 用户退出代理后的实测

- Chrome重新探测仍返回`BROWSER_LAUNCH_FAILED`。
- 单独启用真实PDF闭环测试，实际在运行探针的渲染子进程阶段失败，未创建可见试卷或冷却。此测试使用临时数据库的测试审题记录，不操作运行库。
- 本地`127.0.0.1`随机端口绑定返回`PermissionError`（errno 1），因此不能在此环境启动HTTP服务做浏览器页面联调。
- 直连npm仓库仍为`Could not resolve host: registry.npmjs.org`。
- 在两个新临时目录尝试依赖重装，未动既有node_modules/venv。npm离线安装因vue-tsc包无缓存失败；Python新venv离线安装因alembic缓存缺失失败。干净联网安装仍未验证，既有环境的测试/构建已通过。

这些是当前执行环境的实测限制，不能通过假定用户已关闭代理就标为解决。

## 普通终端复验

先在工程根目录构建打印资源：

```bash
npm run build:print
PAPR_TEST_REAL_PDF=1 backend/.venv/bin/python -m pytest -q backend/tests/test_paper_execution.py::test_real_pdf_end_to_end
```

真实测试将运行探针→受理→数学子进程→Chrome两版PDF→CoreGraphics解析→文件保存→成功事务→鉴权下载→再次解析；无需运行HTTP服务，不读取/修改运行库。默认使用本机Node22、Chrome和Arial Unicode，可用`PAPR_PDF_NODE`、`PAPR_PDF_BROWSER`、`PAPR_PDF_FONT`覆盖绝对路径。

正式运行方式及API/worker环境配置见README。实际运行库内容需要管理员自行完成验证、审题和发布；旧注册指纹若与当前代码不一致不能跳过校验。
