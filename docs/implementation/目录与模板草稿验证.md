# 目录与模板草稿验证

日期：2026-10-27，北京时间。本批串行承担T0迁移/契约、T2草稿存储与T6只读概览；未启动子代理。

## 本批实现

- 0003新增14张表：来源、目录、节点、知识点与修订、目录映射、目标与修订、生成器、模板与版本、目标关联、profile和固定用例。Alembic保持唯一head；时间存储继续为固定微秒`+08:00`。
- `seed-content --admin-username …`仅接受已存在且启用的管理员，读取工程内固定种子；不创建账号、不接受在线脚本。数学/schema检查在写事务外完成，整批入库使用一个BEGIN IMMEDIATE事务。
- 首次导入20条记录：两册候选目录（下册暂为空）、一个乘法主题、O002及修订、一个训练目标及修订、一个生成器、MUL_VERTICAL草稿及关联、两个profile和五个固定用例，以及来源/目录映射。
- 稳定UUID与唯一编码支持重复及并发导入；重放逐字段核对，保留首次时间。不一致时拒绝覆盖，唯一编码冲突导致整批回滚。相同生成器key/version的指纹不一致同样拒绝，不借导入命令偷偷升级算法。
- 知识点/目标当前修订指针在对应修订插入后设置。模板发布指针保持NULL，profile有效题量仍为空；不写正式validation_run、review、release，不增加content_epoch。
- 管理端新增`GET /admin/api/v1/catalogs`、`GET /admin/api/v1/templates`，offset/limit分页（默认50、最多100），返回总数、稳定顺序列表和no-store。只接受管理员会话；未提供公共草稿查询或发布接口。
- 管理页面加载真实列表，明确展示候选核验状态与“尚未发布”；概览各展示最多100条，超过时提示。时间显式北京时间。共享类型/OpenAPI同步生成。

关联表统一复用Record，因此catalog_knowledge、template_objective等同时有created_at和updated_at；这比原字典增加updated_at，不改变其业务含义。当前只读及固定种子路径保证指针归属与目标关系；任意编辑、父节点移动、不可变发布版本及发布事务约束仍待后续服务实现，不能仅凭这些外键宣称全部业务规则已完成。

## 使用与后续

已有管理员的本地开发库可执行：

```bash
backend/.venv/bin/alembic -c backend/alembic.ini upgrade head
backend/.venv/bin/python scripts/papr.py seed-content --admin-username admin
```

无管理员时先按README执行`init-admin`，用户名参数替换为实际账号。导入失败不会覆盖现有内容；先检查账号状态、迁移及是否已有人工修改，不通过清空库来绕过冲突。

下一步是草稿聚合详情/编辑、后台持久验证任务、绑定hash的审题与发布。再连接用户配置、出卷worker、两版PDF和完整成功冷却事务。本批没有把这些待办伪装为已可用功能。
